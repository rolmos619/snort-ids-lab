# Snort IDS Lab

## Overview

This project documents the configuration and testing of a Snort
network intrusion detection system in a VirtualBox lab.

The work includes identifying the monitoring interface, validating
the Snort configuration, capturing network traffic, testing two
custom detection rules, and analyzing a recorded packet capture.

## Lab Environment

| Component | Role |
|---|---|
| Ubuntu 22.04 LTS | Snort IDS host |
| Snort 2.9.15.1 | Network traffic inspection and alert generation |
| Kali Linux | Designated attacker VM |
| Metasploitable 2 | Designated victim VM |
| Oracle VirtualBox | Virtualization platform |
| SandBox1 NAT Network | Shared virtual lab network |

The Snort VM used interface `enp0s3` with IPv4 address
`10.0.2.5/24`. Its VirtualBox adapter used promiscuous mode
set to `Allow VMs`.

Kali and Metasploitable 2 were included in the lab environment.
This project does not claim an exploitation test against
Metasploitable 2.

## Objectives

- Identify the Snort VM's default interface and network address.
- Validate the Snort configuration.
- Demonstrate packet capture in sniffer mode.
- Create and test custom ICMP and TCP-content rules.
- Analyze a PCAP and count generated alerts.
- Document results with screenshots.

## Results

| Test | Observed result |
|---|---|
| Configuration validation | Successfully validated |
| Sniffer-mode test | Captured TCP packet headers |
| ICMP rule test | Eight alerts for four ping requests and four replies |
| TCP-content rule test | Successful `root detected!` alert |
| Offline PCAP analysis | 302 alert-output lines |

The alert count represents rule matches, not 302 confirmed attacks.

## Custom Rules

The following temporary rules were tested:

```snort
alert icmp any any -> any any (msg:"ICMP packet detected!"; sid:1000002;)
alert tcp any any -> any any (msg:"root detected!"; content:"root"; sid:1000001;)
```

The ICMP rule matched traffic generated by:

```bash
ping -c 4 10.0.2.1
```

The TCP-content rule matched a known test string in a plaintext
HTTP request.

## Troubleshooting and Adaptations

The walkthrough's HTTP test endpoint returned a domain-parking
page rather than the expected test content.

To provide a known test string, I added `?root` to the request:

```bash
curl 'http://testmynids.org/uid/index.html?root'
```

The successful test used Snort with checksum verification disabled:

```bash
sudo snort -A console -k none -i enp0s3 -c /etc/snort/snort.conf
```

Snort generated an alert with SID `1000001`.

This verified content matching in an outgoing HTTP request.
It did not demonstrate a root compromise. The checksum adjustment
was used for lab troubleshooting, not as a general production
configuration recommendation.

## Offline PCAP Analysis

Both temporary custom rules were commented out before analysis.

The capture was processed using:

```bash
sudo snort -A console -c /etc/snort/snort.conf -r case001.pcap > snort.out
```

The output was counted and inspected using:

```bash
wc -l snort.out
head -n 5 snort.out
```

The analysis produced 302 alert-output lines. Sample alert messages
included:

- BAD-TRAFFIC same SRC/DST
- DNS SPOOF query response with TTL of 1 min. and no authority
- SCAN UPnP service discover attempt
